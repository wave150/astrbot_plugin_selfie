# 真实世界生活相机 · ta的一天 · 新手上手指南

作者：**wave150**　|　当前版本：**v1.6.9**　|　仓库：<https://github.com/wave150/astrbot_plugin_selfie>

我会拍照片，也会过日子。我住在一座真实的城市里，有家、有当地的天气，还有每天的日程和随时冒出来的事——到点出门上班，饿了去吃饭，天冷了换衣服，晚上回家睡觉；在这些生活的现场，我举起手机拍自拍、拍特写，有时候也和你拍一张互动照。照片里我在哪、在做什么、穿着什么，都是从这一天推出来的；日程表、日记、相册和 QQ 空间说说，也都是同一条生活线上长出来的东西。  
**我不再自带默认形象**：长相、发型、衣服全部来自你上传的参考图，同一个插件实例只养一个角色。

下面按顺序做 6 步，就能出第一张图。

---

## 一、从零到第一张自拍（6 步）

### 第 1 步：下载安装

插件仓库：<https://github.com/wave150/astrbot_plugin_selfie>（源码、更新说明、问题反馈都在这里）

三种装法选一种，装完都要在插件管理里**重载插件**：

1. **插件市场**（推荐）：AstrBot WebUI → 插件 → 插件市场 → 搜索「真实世界生活相机」→ 安装；
2. **Git 安装**：在 AstrBot 的 `data/plugins/` 目录里执行 `git clone https://github.com/wave150/astrbot_plugin_selfie.git`，以后 `git pull` 就能更新；
3. **手动安装**：在仓库的 Releases 页面下载最新 zip，解压后把整个 `astrbot_plugin_selfie` 文件夹放进 AstrBot 的插件目录。

### 第 2 步：配置生图站（主站必填，副站推荐但不强制）

插件自己不会生图，需要你有一个兼容 OpenAI 图片接口的生图服务（常见的中转站、API 站都行）。准备好两样东西：

- **生图地址**：形如 `https://xxx.com/v1`，一般以 `/v1` 结尾；
- **生图密钥**：服务商给你的 API Key。

到 AstrBot 的插件配置里填这几项：

| 配置项 | 怎么填 |
|---|---|
| `api_base` | 生图主站地址，例如 `https://xxx.com/v1` |
| `api_key` | 主站密钥 |
| `model` | 生图模型名，默认 `gpt-image-2.5-flare`；填你服务商实际支持的模型 |
| `image_size` | 出图尺寸，默认 `1024x1792`（竖图，接近手机自拍比例） |

**推荐再配一组副站**（`api_base_backup` / `api_key_backup`）：主站偶尔抽风或被限流时，副站顶上，不至于一张都出不来；不配也能用，只是主站失败就直接报错。

> 小提示：这个服务必须支持「带参考图生成」（接口里的 `/images/edits`）。只支持纯文字生图的服务，拍出来的人不会像她。  
> 密钥只填在 AstrBot 配置里，不要发到群里或截图公开。

### 第 3 步：上传角色参考图（最重要的一步）

**插件不再内置任何默认形象，也不再随包发布参考图**：长相、发型和默认衣服全靠你在「参考图」页上传的这几张图。

1. 重载插件，打开插件页里的「自拍工作台 → 参考图」（第一页）；
2. 点「打开本地文件」上传一张**正面、全身或大半身、背景干净、光线均匀、没有遮挡**的角色图，裁好后在主站参考图 1 里选它；
3. 想更像：再上传一张**脸部特写**，勾「生图站支持双参考图」，把它填进主站参考图 2；
4. 如果副站只收 1 张图（很常见）：上传一张**身体和脸合并**的图，勾「启用副站参考图」+「副站只有单参考图」，把合成图填进副站参考图 1；
5. 点「保存主站/副站设置」，下一张自拍就用新图，不用重启插件。

支持 png / jpg / webp；建议竖版 9:16 或 1024×1536 左右，分辨率不用特别高，脸和衣服看得清就行。上传时长边超过 1536 会自动缩小，页面里也能直接框选裁剪。

> 没有填参考图时不会出图，会提示你回这一页上传——所以第 3 步一定要做。

**想给她准备几套可以点单换的衣服**：给某张衣服参考图点「衣服设置」起个名字（例如「冬装」），可以勾上「可摘帽子 / 可脱外套」；生图测试的「参考图衣服（参考图页）」里就能直接选这套，改名后下拉会跟着变。

**夜间素颜（可选）**：在「参考图」页勾「启用素颜」，并上传一张**素颜三视图**（卸妆状态的脸）。**素颜时间为 22:00 到次日 07:00**，只在室内睡觉房间生效（家里的床、旅店床、青旅床位；网吧包厢和事件场景不算）。

**想按天气换整套衣服（例如降温换冬装）**：在参考图页上传冬装参考图，加一条「当日平均气温低于 x℃」的条件参考图，把主站 / 副站要换的位置选上它。

**换装只贴头部参考图**：点单换装、随机衣服特写、事件服装、睡衣这些「衣服由提示词决定」的场合，只上传你的头部参考图（主站参考图 2）来核对脸和发型，不贴全身图，避免参考图里的旧衣服串到新衣服上。参考图页启用的素颜生效时只贴素颜三视图。

### 第 4 步：设定家的地址（必做）

插件**不内置任何城市**。打开工作台的「世界设置」页，在「首次设定家」里选城市 → 查询城市 → 选区县 → 点「设定家并生成 50 个地点」。她会现场生成这座城市的 50 个地点和区县拓扑（会调用一次文本模型，通常 1–3 分钟；失败不会写入任何数据，可以重试）。生成完成后才能保存世界设置、开始自拍。

顺便可以在同一个「家」卡片里改：
- **房间环境**：家里的厨房、客厅、卧室等房间的详细描述，生图按原文用；
- **夜间睡衣**：22:00 后自拍会从这里随机挑一套，可以增删改（至少留一套）；只填衣服本身，姿势、动作和场景由动作库 / 场景库决定。内置的 7 套默认就列在这里，老实例打开这一栏也能直接看到并编辑。

### 第 5 步：在生图测试里生成第一张

打开「自拍工作台 → 生图测试」：

1. 选城市 → 区 → 地点；第一次验收形象建议在「家（房间）」分类里选一个房间；
2. 服装和动作先用默认的，勾上「我已了解并确认会产生费用」，点「生成测试图」；
3. 生成过程中可以点「取消生图」；这张图只给你看，不发群、不扣普通用户额度、不写照片记忆；
4. 像不像主要看第 3 步那几张参考图；不像就回参考图页换一张更清晰、更正面的图再试。

### 第 6 步：在 QQ 里对话生成第一张

在 QQ 里 @ 她（私聊直接说），然后发：

```text
自拍一张
```

正常情况下她会先像平时聊天一样回你一句（第一句末尾带「（咔嚓）」表示接单），然后**单独发一张图**——照片内容她自己记着，不会再补文字说明。第一次出图可能需要等几十秒，属于正常现象。

如果没反应或报错，先跳到最后的「常见问题」；报错里说没有参考图的，就是第 3 步还没填好。

### 顺手设置（可选）

- `character_name`：**角色名字**，只用于称呼、群聊里叫她和照片记忆归属，不描述长相；留空也能用；
- 聊天里的接单话、配文和空间说说都会优先用 AstrBot 当前会话的人格设定；
- 其他配置项（额度、cos、学习、日记同步等）见文末的「配置说明」。

## 二、日常玩法

### 指令总表

本插件没有 `/` 开头的命令，全部用自然语言触发。私聊直接说；群聊要先 @ 她，或者在句子里带上她的名字（配置项 `character_name`，留空就只能靠 @）。下面这些说法可以夹在句子里，不要求一字不差。

| 想做什么 | 可以这样说 | 说明 |
|---|---|---|
| 自拍 | `自拍一张`、`拍张照片`、`看看你`、`你长什么样` | 按当前时间、地点、天气和衣服拍一张；普通用户受每日额度和 `selfie_probability` 影响，可能回「现在不太想拍嘛」 |
| 特写 | `特写`、`来张特写`、`拍个特写` | 近距离特写；场景、天气、衣服、额度和自拍完全共用 |
| 特殊特写 | `特写pm`、`pm特写` | 只有配置了 `closeup_pm_ids` 才和普通特写有区别：只从指定编号里抽；留空就等同于普通特写 |
| 随机衣服特写 | `随机衣服特写`、`随便穿一套衣服来个特写`、`抽一套衣服特写`、`随机换装特写` | 先报衣柜总套数，再随机抽一套衣服 + 一条特写出图；只在家里/住宿可用，管理员可 `admin随机衣服特写` 随时测试 |
| 点菜换装 | `换女仆装再拍一张`、`穿婚纱自拍`、`来套汉服拍一张`、`穿那件粉色洛丽塔裙拍一张` | 家里/住宿可当场换；其它地点会先婉拒、仍按当前衣服拍；衣柜没收录的会现编一套；管理员不限地点和时段 |
| 单张指定风格 | `用二次元风格拍一张`、`用写实风格拍一张`、`真人风格特写`、`玩偶自拍`、`毛绒玩具特写`、`fumo自拍`、`公仔自拍`、`二头身自拍` | 只影响这一张；优先级：本句点名 > 该用户的长期偏好 > 配置默认 |
| 长期风格偏好 | `自拍风格改为二次元`、`以后都用写实`、`以后拍照用二次元`、`自拍风格改为玩偶`、`我喜欢fumo` | 按 QQ 号记住；之后她给你拍的照片都用这个风格，直到再次修改 |
| cosplay | `cos 初音未来 自拍一张`、`cosplay 雷姆 来张特写`、`扮演明日香拍一张` | 先上网搜角色图、发候选给你确认；回「是」才生成；只在家里/住宿且时段允许，管理员任意 |
| cos 确认 / 否定 | `是`、`对`、`就是这个`；`不是`、`换一个` | 只在刚发完 cos 候选、等她确认时有效；「不是」会换下一个候选 |
| 互动 | `摸摸`、`捏捏`、`戳戳`、`揉揉`、`拍拍`（语句里出现任意一个即可） | 按触发词去 `interaction.txt` 匹配行首动作词：匹配到多条随机抽一条出图；库里没有这个词的提示词就只回一句害羞的话（「有点害羞」「过一会嘛」这类），不生成照片；共用场景/衣服/额度 |
| 学衣服（管理员默认） | `学习这件衣服`、`学会这套穿搭`、`收录这套服装` + 发一张参考图 | 看图提取后写进 `costumes.txt`，自动试拍一张；回「是」保留，回「不是」删掉刚学的那条 |
| 学造型（管理员默认） | `学习这个造型`、`记一下这个姿势`、`学会这个构图` + 发一张参考图 | 写进 `closeup_prompts.txt`，试拍和确认规则同上 |
| 取消学习 | `算了`、`不用了`、`取消`、`先不学了` | 在等她发参考图时有效 |
| 摘帽子 / 脱外套 | `摘掉帽子再拍一张`、`不要戴帽子拍一张`、`脱掉外套再拍一张` | **只对管理员生效**，普通成员说这些不会改变衣服 |
| 想指定地点 / 背景 | `去海边拍一张`、`换个场景拍一张`、`背景换成咖啡店再拍一张` | 她的活动按自己的日程安排，不会照点单瞬移；会先婉拒，再按当时所在地拍 |
| 管理员通用 | `admin自拍 女仆装`、`admin特写14`、`admin随机衣服特写`、`admin摸摸2`、`admin cos 初音未来 自拍一张` | 只在 `admins_id`（或未配置时的 AstrBot 全局管理员）生效；不限额度、不限换装时段和地点，`admin特写N` 可点名提示词编号 |
| 发空间说说（管理员） | `发空间说说，配张自拍`、`空间说说 照片` | 需要装好 QQ 空间配套插件并开启相关配置；会立即发一条带图说说 |

> 普通用户每天最多拍 `daily_limit` 张（默认 15），管理员不限；每张图都会真实调用生图服务、产生费用。
> 她正在生成上一张时会回「等我拍完这张嘛～」，等这张结束再说下一句。
> 工作台的生图测试、素材入库、城市/事件编辑和日程查看见第三节，不属于聊天指令；工作台测试图不扣普通用户额度，但仍会真实调用生图服务。

### 自拍

```text
自拍一张
拍张照片
看看你
```

她会按当前时间、地点、天气、衣服自动挑场景。白天在外面，晚上在家穿睡衣，下雪会穿厚外套……这些是她自己安排的。

**表情和手势**：自拍动作从数据目录的 `selfie_actions.txt` 随机抽一条（名字 | 表情 | 手势），默认自带 15 条（歪头比耶、脸颊比心、戳脸颊、手背托腮、挥手、撩头发、捂嘴偷笑、食指抵唇、双手捧脸、竖大拇指、手放脑后、比半个心、戳镜头、抬手挡太阳、剪刀手贴脸），也可以在「添加素材 → 自拍动作」里自己加。

**在家时每次换房间**：她的日程决定「在不在家」，照片再决定「在家里的哪个房间」——每次自拍都从工作台「世界设置」里的六个房间（厨房、餐厅、客厅、卧室、书房、阳台）随机抽一间，连拍几张不会全在客厅；**22:00 之后锁在卧室**；**11:00–12:00 在家就是在厨房做午饭**，照片里会带锅、食材、刀工和热气，12:00–13:00 在厨房餐桌吃饭。

**光线跟着真实时间走**：提示词会按这张照片锁定的钟点补一条时段约束（清晨 / 上午 / 中午 / 下午 / 傍晚 / 晚上 / 深夜），**22:00–05:00 一律写「窗外是夜色、屋里只开暖色灯、照片里不能出现白天的日光」**，所以深夜的自拍不会出现窗外是大白天的照片；睡觉、网吧这类本身写死了灯光的动作不会叠加这条。

### 回复风格：拟人化拍照对话（默认开）

配置项 `natural_chat`（默认开）决定整段拍照对话怎么包装：

1. **接单**：先按当前人格和聊天上下文正常回你这句话（你问什么就答什么），**第一句话末尾带「（咔嚓）」**——例如「刚在流水线站了一上午（咔嚓），手都酸了，正好拍给你看」。这个拟声词由 `shutter_mark`（默认开）单独控制，关掉就只正常回应、不加（咔嚓），接单照样生效；
2. **发图**：图片**单独发**，不带任何文字；
3. **发完就结束**：不再补一句解释照片的话。照片里是什么（在哪个房间、穿什么、在做什么、什么表情）会由她自己记进自拍记录、相册和日记，聊天里不出现这段描述。

**照片描述只进记忆**：模型生成的第一人称描述只用于相册 / 日记 / 之后的照片记忆，不发送到聊天；描述里同样不会出现「刚从外面回来」「刚下班」这类交代行踪的句子。

**分段回复**：接单话按 AstrBot 全局设置里的「分段回复」（`platform_settings.segmented_reply`）来拆：跟随里面的启用开关、`split_mode`（regex / words）、正则、分段词、字数阈值和内容清洗规则，并用同样的 1~2 秒间隔逐条发送；不管那边怎么配，句号都不会出现在聊天文本里，句号处一定分开。发图之后没有文字，所以不再涉及配文分段。

人格和上下文取自 AstrBot 当前会话的人格设定与最近的聊天记录。没配文本模型或调用失败时自动退回旧格式（短句 + 🤳 接单、图片带固定配文），不会卡住出图；把 `natural_chat` 关掉则完全回到旧行为。

**文本模型偶发超时不影响体验**：接单有兜底；如果模型一次没在规定时间内回（例如 `TimeoutError`），会用更长的时限自动重试一次，重试也失败才用兜底短句。照片描述那次调用用户看不到结果，只等 12 秒、不重试，拿不到就用固定配文存档。

**接单话不会一直说「行行行」**：她此刻在哪、在做什么以当前场景为准，不会编「刚从外面回来 / 刚下班」这种没发生的行程；最近几次接单说过的话会作为「别重复」的参考一起给模型，所以每次说法不一样，敷衍口头禅（行行行、行吧行吧、好好好、来了来了）会被过滤掉、换一句。照片描述同理：出现「刚…」交代行踪的句子会被删掉。

### 特写

```text
特写
```

和自拍共用场景、天气、衣服和额度，只是把「手机前置自拍」换成近距离特写。

如果配置了 `closeup_pm_ids`（例如 `2,6`），只有说「特写pm」或「pm特写」时才会抽到这几条特殊提示词；普通「特写」不会抽到它们。`closeup_pm_ids` 留空时两者没有区别。

### 随机衣服特写

```text
随机衣服特写
随便穿一套衣服来个特写
抽一套衣服特写
随机换装特写
```

她会先数一遍衣柜（`costumes.txt`）里一共有多少套，再随机抽一套衣服、随机抽一条特写，把「一共几套、随机到第几套、第几条特写」告诉你，然后出图。适合「今天穿什么由你决定」的时候。

- 只在家里或在外住宿（酒店、旅馆、青旅等）能换装的地点可用；白天在街上会被婉拒；
- 管理员可以用 `admin随机衣服特写` 在任意时间、任意地点测试；
- 和普通特写一样占每日额度、进相册和照片记忆，**不会**写进衣柜或特写库。

### 换衣服（点菜）

在她**在家**或**住旅馆/酒店/青旅**的时候，可以直接说：

```text
换女仆装再拍一张
穿婚纱自拍
来套汉服拍一张
```

没收录过的衣服，她也会现编一套穿上。衣服库在数据目录的 `costumes.txt`（插件目录里的同名文件只是安装时的默认值），每行一套：`名字 | 别名 | 描述`。

**换装只贴头部参考图**：换装出图时不再上传「穿着参考图那套衣服的全身照」——衣服完全按这次点单的提示词拍，参考图只用来核对脸和发型。双参考图站点贴 `ref_real_face`（正脸）+ `ref_real_head_side`（侧头），单参考图站点（副站）只贴 `ref_real_face`；这样参考图里的黄色外套、短热裤不会串到新衣服上。夜里睡觉房间换睡衣时，如果素颜参考图生效，就只贴素颜三视图（它本身就是多角度脸部）。随机衣服特写、事件服装、睡衣、校服这些「衣服由提示词决定」的场合都走同一套规则；不换装的日常自拍仍贴原来的全身参考图。

### 三种画风与三视图

支持 `realistic` 真人、`anime` 二次元与 `doll` 玩偶，玩偶是毛绒公仔实物摄影：短小二头身比例、绣线五官、布料与缝线，不是真人皮肤，也不是普通二次元人物插画

每种画风都要先在「参考图」页上传一张包含正面、侧面、背面的三视图，再设置给对应画风：真人沿用主站参考图 1（或已启用的副站参考图 1），二次元 / 玩偶在新增的独立卡片选择并保存；不同画风不借图，缺图会先提示上传，不会发起生图

例如「玩偶自拍」「毛绒玩具特写」「公仔自拍」「fumo 自拍」「二头身自拍」指定本次玩偶画风；「自拍风格改为玩偶」「以后都用玩偶」「我喜欢 fumo」会保存该用户偏好，之后普通拍照默认玩偶，本次说「真人自拍」仍可临时覆盖；配置 `style=doll` 则设置全局默认

玩偶画风支持普通自拍、文字特写、互动、换装与 cos，姿势会按短小玩偶四肢改编。玩偶自拍用一只短手在身边握自拍杆，镜头距离由杆身提供；只露手柄和部分杆身，不让手机或倒影入镜；玩偶随机特写不抽线稿序号，但明确指定线稿编号或在工作台手动选择线稿时仍可使用：身份只能来自自己上传并设置的玩偶三视图，线稿只指导动作与构图，缺少玩偶三视图就提示先上传，不会借真人身份图；其它画风的线稿沿用原有真人规则

旧真人槽位保持不变，无须迁移，原先靠真人图生成二次元的用户需补传自己的二次元三视图；上传内容是否真的包含三个视角由用户确认，目前不额外调用看图模型审核三视图

### cosplay

```text
cos 初音未来 自拍一张
```

cos 前会先去网上找角色图、发给你确认，确认后再拍，只在家里/住宿且允许换装的时段可用，白天在外面会被婉拒

**cos 智能搜图**：`cos_smart_search` 默认开启，先用当前对话模型推测角色全名、所属作品和中英日别名，生成搜图关键词和可选的公开 HTTPS 图片直链；保留纯角色名和别名搜索，安全下载并转存最多四张候选。多张时用 AstrBot 默认图片转述模型（未配置时尝试当前模型）挑最可能的一张，半身图也可参与；只有一张则直接发，排序失败则发搜索顺序的首张。模型不决定是否匹配，角色和服装由用户确认后才生图。单次模型最多等 15 秒，整个智能搜索最多等 60 秒；不会额外调用生图中转站的文字接口，模型调用可能产生额外费用

例如说「cos 明日香」后，Bot 会发候选照片并标出角色名和作品，回「是」才开始生成；回「不是」会排除刚才的图片并重新找（同一网址或相同文件不会再发）；回「不是，是 EVA 的那个」或「不是，要红色战斗服」会把原请求与最新纠正一起交给模型重新查找，找到后再次发图确认，不会丢掉原来的角色名；不能保证每次都能搜到人物匹配且服装可见的图，找不到会明确提示，补充全名 / 作品 / 服装版本可帮助搜索

插件会并行查询 Bangumi、AniList、维基百科和萌娘百科，萌娘百科不是必需来源；如果 AstrBot 已启用并配置 SerpApi，也会使用 Google 图片搜索；候选不要求是百科首图或全身图，最终由用户确认是否合适

关闭 `cos_smart_search` 则恢复原有关键词搜图和确认流程；`cos_search_hint` 可填写搜索偏好，但不会覆盖你明确指定的角色、作品或服装

参考图页要先填好她自己的参考图：cos 出图时**她自己的图是第一张参考图**（写实风格用头部参考图，夜里睡觉房间用素颜三视图；二次元 / 玩偶使用各自在参考图页独立设置的三视图），角色图只是第二张，单图站点会改成「先描述角色服装和头发，再单图生成」。没填参考图时会提示先去「自拍工作台 → 参考图」上传。

发型默认也一起换成 cos 角色的：配置项 `cos_hair_from_character`（默认开）打开时，照片里的头发颜色、发型和长度跟角色走，脸仍然是她自己的；关掉后只换角色的服装和配饰，头发保持她自己参考图里的样子。双参考图站点直接贴角色图，单参考图站点会让看图模型把角色的发型一起描述进提示词。

脸是硬性约束：cos 照片里的脸必须是参考图1里她本人那张脸的一比一复刻，眼睛大小和眼距、鼻子、嘴型、脸型轮廓、下颌线和肤色都不许改，也不许美颜；角色图只取服装、配饰（连头发一起换时再加上发型和发色），角色图的脸和五官一律不要，提示词开头会写清「两张参考图不是同一个人」、结尾再强调一次，负面词里也禁止换脸。自拍、特写、互动特写三条 cos 路径都生效。如果换了某个生图站还是明显不像，说明那个模型在多图参考时会优先抄第二张脸，换一个多图参考更听话的站点会更稳。

### 互动

```text
摸摸
捏捏
戳戳
揉揉
拍拍
```

语句里出现任意一个互动触发词（摸摸 / 捏捏 / 戳戳 / 揉揉 / 拍拍）就会去 `interaction.txt` 里按行首动作词匹配：

- **匹配到多条**：随机抽一条作为这次的提示词出图（不会连着两次抽到同一条）；
- **一条也没有**（例如库里暂时没有以「戳戳」开头的提示词）：她只回一句害羞的话（「有点害羞」「过一会嘛」这类），**不会生成照片**；
- **库里自己新加的动作词**（例如 `亲亲：【贴近镜头】；…`）会自动变成可触发的词，不用改代码；
- 群聊里仍然要先 @ 她或带上她的名字（和自拍 / 特写一样），私聊直接说就行。

互动提示词的格式固定为 `动作词：【机位短语】；正文`，例如：

```text
捏捏：【仰脸俯拍＋双手互动】；蹲低或跪坐在镜头正下方、双膝并拢，仰头对准上方镜头……
```

行首动作词决定这条归哪个触发词；`【】` 里写机位、景别和双手怎么互动，后面用中文分号接正文（建议至少 500 字）。工作台「添加素材 → 互动」的 AI 草稿会按这个格式生成；手动新增 / 编辑时也要符合这个开头，否则会提示格式错误。

**草稿只写「一张照片里定格的那一刻」**：这是拍照提示词，不是视频分镜。AI 草稿会明确避免「先…再…随后…最后…」这类先后过程，也不允许「逐渐 / 慢慢 / 缓缓进入 / 移动 / 轨迹」这类带时间过程的写法；正文只描写按下快门这一刻——手此刻的触点与力度、手指和关节的静态姿态、她的即时反应、身体支撑关系、机位和景别。出图侧还会再补一句「这是一张静止照片」兜底，素材库里旧的分镜式条目也不会把图拍成连续动作。

互动照片用「镜头外伸进来一只手」的互动特写构图，场景、衣服、额度和自拍 / 特写共用；也能在工作台「生图测试 → 动作来源 → 互动（互动库）」里先挑一条定点验收。

## 三、自拍工作台（网页管理页）

重载插件后，在 AstrBot 的插件页面里能找到「自拍工作台」。它不用另外启动服务，跟着 AstrBot 的登录权限走。

工作台分六页：参考图、生图测试、添加素材、世界设置、事件编辑、日程安排。

### 1. 参考图（上传 / 裁剪 / 槽位 / 条件）

**这一页空着是什么意思**：新版本不再内置任何默认形象，也不随包发布参考图——这一页空着就**拍不了照**（会提示你先上传并填好参考图）。第一次用：上传自己的角色图，填进主站参考图 1（可选头部图填参考图 2、单图站点填副站），点保存即可；之后要换角色也是在这一页换图。

**上传**：点「打开本地文件」选图；选完会弹出裁剪窗口——在图上拖一个框（拖框内是移动，拖右下角把手是改大小），点「全图」框选整张，点「确认裁剪」就把裁好的图上传（长边超过 1536 会自动缩到 1536）。不裁剪直接确认也能用，等于整张图等比缩放。**上传只是把图加进下面的图片墙，不会覆盖任何东西，也不会自动替换槽位**——想让它当参考图，还要在槽位里选它并保存。

**主站 / 副站槽位**：

- **主站参考图**：勾「生图站支持双参考图」后分两个槽位——参考图 1 是全身三视图、参考图 2 是头部三视图；不勾就只用参考图 1。每个槽位都能单独「上传/更换」「清除」。
- **副站参考图**：先勾「启用副站参考图」；再勾「副站只有单参考图」决定副站填一张还是两张（槽位 1 必填、槽位 2 可选）。
- 勾选项改完要点「保存主站/副站设置」；上传/更换/清除会立即写入。
- 页面上的图和条件参考图优先于原来的自动挑图：没配置这一页时，出图完全按原来的规则（内置三视图 + 头部参考图），配置之后按这里的槽位贴图。

**夜间素颜参考图**：勾上「启用素颜」并上传一张**素颜三视图**（卸妆状态的脸，正脸/侧脸/背面都行）之后，**素颜时间为 22:00 到次日 07:00**——这段时间在室内睡觉房间（家里的床、旅店床、青旅床位；网吧包厢和事件场景不算）拍的照片，脸部参考图会换成这张素颜三视图，夜里卸妆后的样子更自然。勾了「启用素颜」却没上传图时保存会提示先上传；点「保存素颜设置」才写入，上传照片会顺带自动勾上启用。这一项不再需要改任何配置项，页面上的勾选和照片就是全部设置。**夜间素颜优先于条件参考图**：睡觉房间拍照时条件参考图（气温 / 日期 / 概率）这晚不参与，不会因为当天冷就被冬装条件里的带妆脸顶掉，也不再把冬装套在床上的睡衣上。

**已上传的参考图墙**：缩略图墙显示每张图的名字、尺寸、被哪些槽位和条件用着，可以改名、删除；删掉被条件用到的图时，只会清掉条件里用到它的那个位置（条件本身保留，所有位置都空了才整条删掉），并提示清掉了多少处。

**条件参考图**：每条条件 = 一个触发条件 + 主站 / 副站的参考图设置。触发条件有三种：

| 条件 | 填什么 | 举例 |
|---|---|---|
| 当日平均气温 | 低于 / 高于 x℃ | 低于 10℃ 就换冬装参考图 |
| 指定日期范围 | 从 xx 年 x 月 x 日 到 xx 年 x 月 x 日 | 12 月 24 号到 12 月 26 号换圣诞参考图、12 月 1 号到次年 2 月底换冬装参考图 |
| 每天概率 | 百分之 x | 30% 概率今天换成这套衣服 |

- **日期范围怎么填**：开始日期必填；**结束日期留空＝只在开始那一天生效**；**年份留空＝每年这段日期都生效**（填了年份就是具体那一年的范围，结束日期比开始小会自动按跨年算，例如 2026-12-01 到次年 01-05）。

- 每条条件下面直接列出 **主站参考图1 / 主站参考图2 / 副站参考图1 / 副站参考图2** 四个下拉，各选一张；选「不替换」的位置保持默认参考图。**同一个触发条件写一条就能同时设好主站和副站**（例如「低于 10℃：主站换棉衣套装、副站换棉衣单图」），不用再为同一个温度写两条。
- 优先级 **日期 > 气温 > 概率 > 默认参考图**；同一个位置有多条条件同时命中时取优先级最高的那条，不同位置互不影响（例如日期条件换主站图 1、气温条件换副站图 1 可以同时生效）。
- 主站参考图2 只在勾了「生图站支持双参考图」时生效；副站参考图2 只在副站没勾「副站只有单参考图」时生效（下拉下面也有这句提示）。
- 气温用每天 7 点那次「当日平均气温」判定（只在参考图页有气温条件时才去查），查不到气温就不触发。
- 概率条件也在同一个 7 点入口摇一次，摇中后整天沿用这一套；7 点前沿用前一天的结论。
- 条件参考图替换了「主站参考图 1（全身）」时，提示词里的默认服装描述会自动让位（整套衣服以参考图为准）；换装、事件服装、睡衣、校服这些明确点单的衣服仍按提示词拍。
- 旧版本保存的条件（一条条件只能选一张图、勾位置）读取时会自动换算成新格式，不用重新填。
- **想按降温换冬装**：在图片墙上传一张冬装参考图，加一条「当日平均气温低于 x℃」的条件，把主站 / 副站要换的位置选上它即可。

**把参考图当衣服用（起名字）**：在图片墙上点某张图的「衣服设置」，给它起个衣服名字（例如「冬装」），再按需要勾「可摘帽子」「可脱外套」——生图测试的**「参考图衣服（参考图页）」**来源里就会多出对应档位：只起名是 1 档（`冬装`），勾了可摘帽多一档「脱帽冬装」，勾了可脱外套多一档「脱外套冬装」，两个都勾再加一档「无帽无外套冬装」，一共 4 档。选中哪一档，这张图就作为整套衣服的参考图（不再靠文字描述衣服），并按档位要求去掉帽子 / 外套；参考图页改名之后，这里的档位名字会跟着变。名字留空表示这张图不当衣服用。

衣服设置里还有一项 **「这张图只做单图参考（不当衣服，不进生图测试）」**：勾上后这张图只当参考图用，即使写了名字也不会出现在生图测试的参考图衣服下拉里，帽/外套档位也不生效——适合只用来做副站单图参考、或者只配槽位的图。

**节日衣服（万圣节 / 圣诞节 / 春节）**：不再由插件内置的文字套装生成。自己上传一张节日衣服参考图，再加一条「指定日期范围」条件（例如 12 月 24 号到 12 月 26 号、年份留空就是每年都有），当天出图就会换成那套参考图；也可以同时给它起个名字，方便在生图测试里直接选。

### 2. 生图测试

选城市 → 区 → 地点。区列表最上面除了城市自己的区县，还有两个专门用来测试的分类：

- **事件**：列出这座城市里所有事件在素材库中命名的场景（事件默认场景和各阶段场景）。选中后会自动填好场景，并带出对应的事件素材（动作/服装）；这些内容只用于测试，不会写进素材库；
- **家（房间）**：列出你在「世界设置」里写的家庭房间。**要先在城市里选中家所在的城市，它才会出现**；选中后场景会自动填成那个房间的描述。
- **过夜（固定场景）**：列出内置的十间过夜房（酒店标准间、小旅馆、青旅上下铺、网吧包厢、洗浴休息厅、民宿阁楼、短租公寓、胶囊舱、招待所等）。房间文字固定复用，但城市、区和天气取当前选择的真实地点；可先用「城市 → 区」选好位置，再选「过夜」挑一间测试。旧的 `-` 地点名仍会显示成“过夜”，新城市不再生成这类地点。

地点下面还有两个可以改的输入框：

- **场景**：选中地点/事件/房间后自动填，也可以自己改；生成时会按这里的内容拍背景。输入框下面会显示当前场景是哪一类（日常地点 / 家 / 过夜 / 事件）。**没有单独的「场景模式」开关**，在地点里选什么就是什么场景；
- **动作**：选事件场景或「事件动作」来源时会自动填事件动作；日常特写 / 自拍 / 互动 / 吃饭 / 睡觉来源留空，动作由下面「动作来源」选中的条目决定。

服装和动作的来源各自独立，先选来源，再选具体条目：

- **线稿参考特写**：先在「添加素材」上传动作白描线稿，再在动作来源选择「线稿参考特写」，右边按特写编号选图，服装与动作卡片下方会显示所选线稿缩略图；文字特写在前、线稿在后统一连续编号，删除前面的条目后显示编号自动前移，内部存储 ID 不改动
- 线稿直接作为第二张参考图送到生图模型，第一张是人物身份参考图，提示词要求严格按人体模型的动作、机位角度和裁切摆姿势；线稿只指导动作，不参考其人物外观或画风；玩偶指定线稿使用玩偶三视图并保持毛绒玩偶，其它画风沿用真人照片规则
- 普通随机特写会把每张已上传线稿作为独立候选，与文字特写一起抽取并避免连续重复；pm 和 cos 随机特写不混入线稿；`admin特写N` 按当前统一显示编号选择，可直接指定文字或线稿
- **仅使用支持至少两张参考图的生图站**：单图主站或副站自动跳过，不会丢弃线稿降级生成，没有可用多图站点则明确提示；两图站点优先发送「清晰面部参考图 / 当前素颜图 + 线稿」，三图及以上站点可再带服装参考图，面部固定第一张、线稿固定第二张、服装第三张
- **线稿特写锁脸**：提示词开头与结尾都要求脸部与参考图1一比一一致，逐项约束五官比例、脸型和肤色；禁止采用或融合线稿人物的长相，线稿头部仅用于朝向和机位，不允许换脸、美颜或改五官
- 生图测试与试穿成功后显示本次总耗时（秒），含提示词准备、重试和图片下载，后台任务恢复后仍可查看


- **服装来源**：先选「日常服装（服装库）」「参考图衣服（参考图页）」「事件服装（事件素材）」或「睡衣（世界设置 → 家）」，再选具体服装。**「睡衣」来源直接列出「世界设置 → 家 → 夜间睡衣」里的那几套**（改了睡衣列表不用先保存，下拉里就是最新的），选中后按这套睡衣换装出图，适合先验收睡衣效果。**「参考图衣服」的选项全部来自参考图页**：给一张参考图起个衣服名字，它就会按勾过的「可摘帽子 / 可脱外套」出 1–4 档（`冬装`、`脱帽冬装`、`脱外套冬装`、`无帽无外套冬装`），选中后整套衣服以那张参考图为准、不换装；参考图页改名 / 改勾选后下拉会立刻同步。勾了「只做单图参考」的图不算衣服，不会出现在这里。原来的「经典 / 冬装经典」八档已经删掉，衣服档位现在全部由参考图页动态决定；日常服装只列素材库里的文本服装；选事件素材时会列出该事件主场景和各阶段用到的服装，只用于测试，**不会写进素材库**；
- **取消生图**：生成过程中旁边会多出「取消生图」按钮，点一下就取消这次付费生图；直接退出自拍工作台（关页 / 刷新 / 回插件列表）也会自动取消还在跑的这次生图，不会在后台白跑（后端另有兜底：90 秒没人轮询就自动取消）；
- **素颜**：服装与动作卡片最下面有一个「素颜」勾选框，勾上后这张测试图强制把脸部参考图换成**参考图页「启用素颜」时上传的那张素颜三视图**，不用等到夜里；只在写实风格下生效。参考图页还没启用素颜时这个勾选框不可用，下面的提示会写去哪开。它和参考图衣服可以叠加，例如「冬装 + 素颜」；
- **动作来源**：先选「日常动作（特写库）」「事件动作（事件素材）」「吃饭（菜品库）」「睡觉（夜间动作）」「自拍（自拍动作库）」或「互动（互动库）」；选「自拍」时「动作 / 特写」下拉列出的是自拍动作（表情 + 手势），生成时按前置摄像头自拍的构图，照片里不出现手机；选「互动」时「动作 / 特写」下拉列出 `interaction.txt` 里的互动提示词（显示动作词 + 编号），生成时按行首动作词走互动特写构图（镜头外伸进来一只手）；选「吃饭」时下面会多出「菜品」下拉，列出素材页添加的菜品（默认 53 道），生成时会把菜、主食和餐具一起写进照片；同时「动作 / 特写」下拉会**只列 5 套吃饭机位**（近景、俯拍、端碗、对面、吃到一半），选哪套就按哪套拍，方便定点检查每一套的效果。选「睡觉」时「动作 / 特写」只列 **00:30 之后的三种过夜拍法**（普通床侧躺、青旅上下铺、网吧包厢趴桌），生成时带「关灯、只有屏幕冷光」的要求，和真实夜里自拍用的是同一份描述。日常动作：再选具体特写 / 事件动作；事件动作下拉列出的是**该事件动作素材库的全部条目**（包括阶段动作随机池里能抽到的动作），每条显示成「动作名称：提示词开头」，选中后把提示词填进上面的「动作」框，仍可自己改；旧数据里名称本身就是提示词片段的条目会自动只显示提示词，不重复两遍；
- 「事件素材来源」下拉只在服装或动作来源选了「事件」时出现；如果地点选的是「事件」场景，事件素材就固定取这个事件；
- 事件场景也能用日常服装 + 日常特写（例如某件衣服想看它在事件场景里什么样），日常场景也能用事件服装 + 事件动作。

确认费用后生成一张预览图。**这张图不发群、不扣普通用户额度、不写照片记忆**，就是给你试效果的。  
下面的「相册」会保存工作台生成的图和聊天里发过的自拍：每页 24 张，用「上一页 / 下一页」翻历史；点开是全屏大图，**双击图片会把那一处放大**，滚轮往上放大、往下缩小（按光标位置缩放），放大后可以拖动查看细节；**点图片外的黑色区域或按 Esc 关闭**，再次双击还原。

生图和 AI 生成都在后台跑：**切换标签页不会中断**；草稿、城市地点这类文本任务关掉页面也会继续，回到页面后会自动接上并在完成时弹提示。**付费生图（生图测试 / 服装试穿）例外**：退出自拍工作台会自动取消这次生图，页面上也有「取消生图」按钮可以随时停下；后台任务徽标旁的「后台任务 N」就是正在跑的任务数。

### 3. 添加素材

选「衣服 / 特写 / 互动 / 菜品 / 自拍动作」，输入文字（也可以附参考图，或者文字+参考图一起），让大模型生成一条草稿。  
草稿会出现在下面的输入框里，**你可以改，改完点确认才会存进去**。

- 衣服草稿可以先生成、再选场景和特写号**试穿**，满意再入库；
- 试穿不写入衣服库、不占编号；
- 特写和互动同样支持参考图，生成的文字建议至少 500 字，动作和镜头会更细；
- **互动**草稿固定为 `动作词：【机位短语】；正文`：动作词从摸摸 / 捏捏 / 戳戳 / 揉揉 / 拍拍里选一个，紧跟 `【】` 机位短语（例如 `捏捏：【仰脸俯拍＋双手互动】；…`），再用中文分号接至少 500 字正文；写进 `interaction.txt`，聊天里的互动触发词和工作台「互动」来源共用这份库。手动编辑旧条目时也要符合这个开头，否则保存会提示格式错误；
- **自拍动作**草稿固定为「名字 | 表情 | 手势」：生成时会额外加一层自拍要求——手机前置摄像头第一人称视角、竖屏近景只拍上半身、照片里不出现手机 / 相机 / 自拍杆、手势只用没拿手机的那只手；写进 `selfie_actions.txt`，日常自拍和生图测试的「自拍」来源共用这份库；
- **菜品**草稿固定为「菜名 | 约100字描述」，描述只写这顿饭本身：盘碗里的菜、主食、餐具和桌面，不写人物；生图测试的「吃饭」动作来源直接从这里选菜，写进 `meals.txt`。默认自带 53 道（与每日菜单一致），老版本升级时会把新增的默认菜一次性补进来，**你改过的描述和自己加的菜都会保留**。

### 4. 世界设置

- **家**：家在哪个城市、哪个区，以及六个房间（厨房、餐厅、客厅、卧室、书房、阳台）的环境描述。房间描述会按原文用于每次家居场景，所以写得越具体，家越稳定。**每次在家自拍会从这六个房间里随机一间**（22:00 后固定卧室，11:00–12:00 固定在厨房做饭、12:00–13:00 在厨房餐桌吃饭）。
- **旅行城市**：她可以自动去哪些城市。
- **每城最少待几天**：防止一天换一个城市。
- **添加新城市**：输入城市名（可加省份）→ 点「查询城市」→ 查到后点「添加该城市到世界表」（只登记查询到的行政区和最少待几天，**不生成地点**）→ 之后就能在「追加地点 / 重新生成城市」里选到这座城市。
- **追加地点 / 重新生成城市**：地点数量可填 **1–100**。**追加**会保留已有地点、区县拓扑和最少停留天数，只补本批地点；重复名称由后端按 NFKC、空白、大小写归一后拒绝（全半角、空格、大小写不同或跨区同名都算重复）。例如原来 50 个地点，再追加 30 个就是 80 个。**重新生成**会替换整座城市资料；新城市仍先生成完整结构（含每区景点、车站和生活场景），完整生成要求数量够用：至少覆盖全部区县、每个区至少 1 个景点、每个车站区县至少 1 个车站；数量不足会被拒绝并提示改用追加模式。追加需要这座城市已经有带坐标的区县资料，刚登记还没生成过的城市会自动按完整生成处理（同样受数量要求限制）。
- **地点怎么排**：新城市会先给每个区安排当地景点（公园、景区、古迹、博物馆、湖山寺庙、老街等），再补生活场景，不会整城都是商场和小学。
- **过夜点不再由城市生成**：城市地点里不会生成酒店、青旅、小旅馆、网吧等过夜点；如果草稿里出现这类地点会被拒绝。角色 18 点还在外面时，从内置的十间固定过夜房抽一间，地区取她当时所在的城市/区，天气也取那里的天气；房间文字固定复用，不再进入普通地点池。网吧包厢和洗浴休息厅不自动换睡衣，床和青旅上下铺会进入睡眠场景。

> 城市名查询走的是本地行政区数据，不花模型钱；生成地点草稿会花 token。  
> 已有生活状态时改「家的城市/区」会被拒绝，避免她突然瞬移；需要先备份再显式迁移。

### 5. 事件编辑

给她安排特殊事件，例如「某天晚上去漫展」「某天下午参加活动」。事件页最上面有「选择已有事件」下拉，可以在电子厂、大上海等已保存事件之间切换查看和编辑；切换会保留当前本地修改，点「保存全部事件」才写入，生图测试页也只使用已保存的事件。

一个事件的结构（v1.5.6，各模块用不同浅色块区分）：

- **一、条件与地点**（浅蓝色块）：周几、日期范围、触发城市、触发概率、开始时间、持续小时（支持跨日），以及事件所在城市/区。
- **二、编写命名素材库**（浅紫色块）：先给这个事件写并命名三类素材——场景库、服装库、动作库。每条素材都有「名称」和「内容」两个输入，并显示「场景 1/2/3」这样的内部编号；服装的「AI 生成」会输出 `名称 | 别名 | 描述` 并自动解析成名称和描述填进去，手工编辑直接改两个输入即可，不要求自己写竖线格式。后面所有选择都从这里引用，不用逐段改正文。素材库下方还有「事件服装随机池」：勾选几套后，每次事件开始随机摇一套、整场沿用。
- **三、阶段随机池（小时偏移）**（浅绿色块）：每个时间块用勾选框选择场景、动作、服装。
  - **阶段名称**：每个阶段顶部有一个「阶段名称」输入（最多 24 字），可以手写，也可以点「AI 总结」按本阶段的场景/动作生成 6–12 字名称（例如「流水线组装」「商场中庭闲逛」）。**日程、日记和自拍配文都优先用它**；不填时退回阶段场景的短名字。
  - **场景**：用一个可搜索的下拉框逐条添加本事件场景（输入「商场」就只剩带「商场」的条目），**每次自拍/特写随机抽一个当背景**（比如商场中庭 / 电梯上 / 商场门口）；第一条是日程、日记和聊天里的主场景，每段至少一条。
  - **动作**：同样用可搜索的下拉框逐条添加（本事件动作或全局特写），**每次拍照随机抽一个**写进这张照片的姿势要求（比如拧螺丝 / 和工友说话 / 伸懒腰），不填就沿用事件默认动作。
  - **服装**：三选一——「跟随事件」（用事件服装随机池，整场一套）、「固定一套」（原来的单选服装）、「沿用前面阶段」（下拉里只显示「沿用阶段 1 / 沿用阶段 2」这样的序号，直接沿用那一段实际穿的那套，比如门club沿用逛商场那套）。子事件内部没有服装随机池，同一场子事件里衣服始终统一。
  - 场景只能选本事件场景库；动作和服装可以选本事件素材，也可以选全局素材库（`costumes.txt` / 特写素材库），本事件素材排在前面。
  - 生图测试的「事件服装」来源会列出该事件的服装随机池 + 固定服装（只用于测试，不写回事件）；「事件动作」来源会列出该事件动作素材库的全部条目（包括阶段动作随机池），显示成「动作名称：提示词开头」，同样只用于测试。
  - 每个阶段底部有「**预览这一抽**」按钮：只在本页抽一次检查素材配得对不对，不生成图片、不写数据；真正拍照时会重新抽。事件结束后的「在附近休息」是独立一幕，不套用阶段池。
- **结束地点（可关闭）**（浅橙色块）：从本事件场景库选择，只在事件结束后的 1 小时内生效，优先于回家。例如 18 点结束，先执行 18–19 点结束场景，再按生活规则回家或就近住宿。开启后可在生图测试的事件地点里检索；关闭后不执行、不列入测试。
- 不再填写事件默认素材；每个阶段选择所需素材即可。每个事件都有独立、稳定的内部 ID，升级会迁移旧 `dashanghai` 等标识并同步运行中的引用。

素材内容可以让大模型先写草稿（按钮会显示「生成中…」，不要重复点），写进素材库后再被引用。建议场景写清地点、布局、陈设、光线与氛围，动作按特写标准写细；生成结果应用后只改本地表单，仍需保存。删除仍被阶段或结束场景引用的素材会被拒绝，先改选再删。

事件地点是独立的，不会混进普通随机地点。改完记得点「保存全部事件」。

**历史备份**：后台会保留事件的历史备份，但界面不提供历史卡，也不提供「查看/恢复」入口；日常编辑和测试请用事件页上方的「选择已有事件」切换当前事件，改完点「保存全部事件」。

> 随机池是实验性功能，但可以随时回退：把勾选全部取消再保存，事件就回到原来的固定场景/固定动作/固定服装玩法；随机池字段是可选的额外字段，旧版本插件读取这些事件时会忽略它们（事件本身照常运行）。整体回退插件版本时，按 [REFACTORING.md](<REFACTORING.md>) 的备份步骤恢复即可，事件历史里也保留着改动前的版本。

> 世界设置和事件页都有「未保存」提示；不想保存就点「放弃未保存修改」。  
> 每页的保存都是显式的，不会点一下就自动存。

### 6. 日程安排

按中国当地时间（Asia/Shanghai，UTC+8）展示今天的课表：已接受计划按起止时间排列、未安排时段明确留空；真实活动以观察时间点单独标注，不把两次观察之间猜成连续活动。角色按整点换场景，同一小时内地点/动作保持不变，所以观察点通常每小时一条；只有到站、事件开始/阶段切换/结束这类真实切换会额外记录。事件准备、阶段和一小时结束场景优先于普通午餐/居家计划。打开页面只读取日程，不重新随机事件或写入未来活动。日记从同一份日程数据中的实际记录提取，不把计划当成已经发生。

### 时间、天气与地点刷新

生图使用实际所选城市与区的天气及当地时间，不再将特写地点固定成西安。天气不可用时不虚构温度或晴雨。追加地点导入成功后立即更新测试选择器，再刷新全表；旧的区名 `-` 仍显示为「过夜」，新城市使用固定过夜房。

## 四、每天的生活和日记

- 她每天有自己的作息：出门、回家、睡觉；默认有 50% 概率留在家到下午 2 点；
- 留家的日子 11:00–12:00 在厨房做饭，12:00–13:00 在厨房餐桌吃刚做好的饭，菜从内置 53 道里每天固定抽一道；
- 做饭和吃饭的照片各自会随机抽一套「机位 + 动作」，要求锅、食材或桌上的饭菜必须入镜：炒菜配米饭和筷子，面/粉可以直接吃，汉堡炸鸡配可乐薯条；
- 出门的日子会在当前片区就近吃午饭；
- 旅行和事件优先，吃饭不会打断正在发生的事；
- 每天结束后，会把**真实发生过的活动**汇总成一篇日记，存在角色数据目录的 `livingmemory` 里。

日记不是另找模型编的，没发生的事不会写；工作台可以看，聊天时也会参考最近几篇。

日记会交给文本模型整理成五段，而不是把时间点堆成一句话：

- **上午**：去了哪里、做了什么；
- **中午**：吃了什么，并带一句真实口吻的评价；
- **下午**：去了哪里、做了什么；
- **晚上**：在哪里落脚住宿；如果晚上有事件，就写晚上做了什么；
- **今日一句**：今天最有意思的一件事，或者吐槽一句今天的烦恼。

整理只允许使用当天实际记录里的时间、地点和事情，**不准编造没去过的地点**（提示词里写死这条规则），输出不合格会自动退回固定格式重排，所以模型抽风也不会丢记录。配置项 `diary_llm_format_enabled`（默认开）可以关掉 AI 整理、只保留固定格式。

旧版本已经写好的日记会在插件加载后自动整理一次（最近 7 天，每 600 秒最多检查一次），整理完会同步更新文件；没有原始活动记录的旧日记会保留原文。如果那天之前已经同步到 LivingMemory，整理后会先删掉旧的那条记忆再写入新格式，避免重复。

### 同步到 LivingMemory（长期记忆）

如果同一个实例里装了 LivingMemory（长期记忆）插件并启用它，自拍插件会把每天的日记写成一条长期记忆：

- 会在 LivingMemory 的 WebUI 记忆列表里看到（关键词搜「日记」或日期即可），聊天时也能被它回忆到；
- 只通过 LivingMemory 自己的 `memory_engine.add_memory` 写入，**不会直接改它的数据库或索引**；
- 记忆作用域（scope）直接跟随 LivingMemory 自己的配置（`memory_scope_mode`，推荐 `user`），按「平台类型名 + 发送者 ID」计算，所以能和平时聊天的记忆一起被召回（v1.5.11 修复：之前误把平台配置 ID 当成平台名，日记会落进一个看不见的独立作用域；旧版本写错的同一天记忆会自动删除后重写）；
- 只写入你实际聊过天的会话；插件启动后会**补写最近的历史日记**（每 600 秒最多检查一次）；
- 同一天同会话只写一次，账本存在插件 `state.json` 的 `livingmemory_diary_synced` 里，删掉某天想重推时可以手动清这一项；
- 配置项：`livingmemory_diary_enabled`（默认开）和 `livingmemory_diary_importance`（默认 0.7）。没装 / 没启用 LivingMemory 时只会安静跳过，**不影响自拍任何功能**。

> 第一次使用：重载插件后等 30 秒左右（插件会自动补写最近 14 天日记），昨天的日记就会出现在 LivingMemory 里；如果之前已经有聊天记录，不需要再发消息。

## 五、照片、额度和费用

- 普通用户每人每天有固定额度（配置 `daily_limit`，默认 15 张），管理员不限；
- 每张图都会真实调用生图服务，会产生费用；工作台里点「测试」或「试穿」也会；
- 生图失败时，她可能会回「手机没电了」之类的话，不会把技术错误直接丢给群友；
- 出图太频繁可能被服务商限流，配置里的 `image_min_gap_seconds` 就是两次尝试的间隔。

**免费玩不了**：这是靠你自己的生图服务出图的，费用由服务商收。

## 六、常见问题

**Q：她完全不出图，只回文字？**  
A：按顺序检查：`api_base` / `api_key` 填了没；`model` 是不是服务商支持的；账户还有没有余额；参考图路径能不能读到。  
工作台「生图测试」能直接告诉你哪一步失败。

**Q：图里不像她 / 每次长得不一样？**  
A：参考图是决定因素。换一张正面、清晰、无遮挡、背景干净的全身图；再加一张脸部特写。  
**纯文字生图不会像她**，插件默认禁止无参考图生成，除非你手动打开 `allow_text_only`。

**Q：为什么晚上她看起来没化妆、冷天又换成了冬装？**  
A：这两件事现在都在工作台「参考图」页设置，不再有配置项。**夜间素颜**：在参考图页勾「启用素颜」并上传一张素颜三视图，**22:00 到次日 07:00** 在室内睡觉房间（家的床、旅店床、青旅床位；网吧包厢和事件场景不算）拍的照片就会换脸。**冬装**：在参考图页上传一张冬装参考图，加一条「当日平均气温低于 x℃」的条件参考图（把主站/副站要换的位置选上它），当天早上 7 点查一次气温、低于阈值就整天用这套；内置角色也可以先点「填入内置参考图」，把内置冬装图导进图片墙再建条件。

**Q：工作台页面打不开或一片空白？**  
A：先重载插件，再刷新页面。新版本加了后端接口和相册，只刷新页面不够。

**Q：改了角色配置没反应？**  
A：改完要重载插件。换角色尤其必须重载。

**Q：家里的房间描述改了，但场景没变？**  
A：保存世界设置后，下一次家居场景才会用新描述；正在生成的那张不会变。

**Q：想换城市，页面说「已有生活状态」不让改？**  
A：这是防止她突然瞬移的保护。先备份数据，再按提示显式迁移或重置世界状态。

**Q：查询城市成功了，但「追加地点 / 重新生成城市」里找不到它？**  
A：查询只是校验。查到后要点查询结果里的「添加该城市到世界表」（只写入行政区和最少停留天数，不生成地点），它才会出现在已有城市列表里；之后再用「追加地点 / 重新生成城市」生成草稿并确认导入。

**Q：怎么在生图测试里试事件场景和家里的房间？**  
A：地点卡里把「区 / 街道」选成「事件」，地点下拉会列出该城市事件各阶段在素材库里命名的场景（每个阶段一行，带阶段编号与小时偏移）；如果事件开启了结束后场景，还会多一行「结束后一小时」。选中后场景会自动填好，再把「服装来源」「动作来源」切到「事件」，就能选事件服装和事件动作（内容来自事件素材库，不写素材库）。测试家里的房间要先在城市里选中家所在的城市，区下拉最上面才会出现「家（房间）」；想测固定过夜房，先选城市和区，再把区下拉切到「过夜（固定场景）」，从地点里挑十间房之一。

**Q：事件页点了「AI 生成」一直转圈？**  
A：按钮会显示「生成中…」，说明文本模型正在返回；等它结束会自动恢复。不要连续重复点，否则会提示上一个操作还没完成。

**Q：生成城市地点时提示「大模型响应超时（单次上限180秒）」？**  
A：这是明确的中文超时提示：单次模型调用最多等 180 秒，已有地点不会被改动。对已有城市使用追加模式，把「本批地点数量」调小（例如 10 或 15）再试；工作台后台任务另有 12 分钟上限，超时也会给出中文提示。不要反复连点，一次点击只发起一次有上界的模型调用。

**Q：日志里出现「[selfie] 拟人回复生成失败，用兜底文案: TimeoutError()」？**  
A：这是接单语 / 配文用的**文本模型**那次调用没在时限内返回，不是生图失败。插件现在会先用 15 秒、超时后加时到 30 秒自动重试一次，两次都失败才用兜底短句；如果经常出现，说明当前这个文本模型本身响应慢，可以在 AstrBot 里给本插件换一个更快的默认对话模型（或者高峰过后再试）。图本身已经正常发出，相册和日记不受影响。

**Q：素材入库时提示「数据已变化，请刷新后重新操作」？**  
A：这是因为草稿生成之后素材库又被改过（最常见的是你刚在素材库里编辑或删除了另一条）。入库只是往文件末尾追加一行，所以插件会自动按最新文件重新挂一次再入库，正常情况下已经不需要你手动重试；如果仍然失败，多半是同一秒内有别的写入占着文件，等一会儿再点「确认入库」即可。内容重复仍会单独提示「素材内容或名称与已有条目重复」。

**Q：参考图页是空的，要不要先填？第一次用不填会怎样？**  
A：**必须填**。新版本不再内置默认形象，参考图页空着时出图会提示你先上传参考图。做法：打开「自拍工作台 → 参考图」，点「打开本地文件」上传自己的角色图，裁好后在主站 / 副站槽位里选它并保存。**上传是新增，不是覆盖**——图片墙只增不删，只有保存槽位时才会替换那个槽位；删图要单独点「删除」。

**Q：节日套装（圣诞 / 万圣节 / 春节）怎么没了？**  
A：内置的节日文字套装已经删掉了，节日衣服改成用参考图：在工作台「参考图」页上传一张节日衣服图，加一条「指定日期」条件（12 月 25 号、10 月 31 号之类），当天出图就会换上那套参考图，比文字描述更像、也更可控。顺便还可以点那张图的「衣服设置」给它起个名字，生图测试里就能直接选这套衣服（含脱帽 / 脱外套档位）。

**Q：让她拍照，好几分钟没动静，或者一张图跑了 10 分钟才出来？**  
A：这是**生图服务排队或某条链路卡住**，不是插件没收到消息。出图期间不会再往聊天里插进度句；单次生图请求最多等 3 分钟，超过就换下一个模型 / 副站，整张图最多 10 分钟，超时会明确回「这张拍太久卡住了，我先停下…」并放掉生成锁，后面的请求能继续接。  
如果频繁出现，看控制台里的 `[selfie] 生图成功 站点 / 模型，用时 XXs` 和 `[selfie] 生图失败（... HTTP ...）`：耗时明显偏长的那个模型可以从 `image_model_fallback` 里去掉，或者把默认 `model` 换成更快的（实测量产时 `gpt-image-2` 通常比 `gpt-image-2.5-flare` 稳）。

**Q：以前编辑过的事件找不到了？**  
A：事件页不提供历史卡或恢复入口；请在页面上方的「选择已有事件」下拉里切换当前事件。后台会保留事件的历史备份，供维护者按需处理，日常编辑不需要（也不应该）直接改历史内容。

**Q：升级后事件里的文字怎么变成「素材库」了？电子厂和大上海还在吗？**  
A：v1.5.5 会把旧事件正文一次性整理成命名素材条目（场景库/服装库/动作库），默认选项和阶段改成引用素材，之后改素材内容即可，不用逐段改正文；这个整理只做一次，不会反复执行。现有电子厂事件会保留；如果事件列表里没有大上海，会自动补回一条独立的大上海事件，不会覆盖电子厂或其它已有事件；只补这一条，不会把同一事件的其它旧版本批量导入。历史备份在后台保留，界面不提供恢复入口。

**Q：第六页「日程安排」里的计划和实际有什么区别？**  
A：计划是引擎已经接受的安排（事件、居家/午餐等），会按时间排成课表；实际只显示真正被观察到的活动时间点，不把两次观察之间猜成连续活动；没有确定安排的时段标为「未安排」。日记只取实际记录，所以不会把计划中的未来活动写进日记。打开日程不会重新随机触发事件。

**Q：事件结束后的场景为什么 18 点结束后 19 点才回家？**  
A：结束场景现在固定只在事件结束后的 1 小时内生效，并且优先于回家。18:00 结束就先执行 18:00–19:00 结束场景，19:00 以后再按可达条件回家或就近住宿。这个效果可以在事件里关闭；关闭后不执行，也不会出现在生图测试里。

**Q：天气和时间是不是还固定成西安？**  
A：v1.5.6 已修正。生图会按实际所选城市、区取天气，并使用中国当地时间（Asia/Shanghai，UTC+8），不再依赖服务器时区或复用角色当前所在地的天气；天气获取失败时显示不可用，不编造温度。

**Q：新城市里没有酒店、青旅、小旅馆、网吧包夜？**  
A：现在城市地点本来就不再生成过夜点，这是设计如此。角色晚上在外时使用内置的十间固定过夜房，按当时所在城市/区取天气；旧城市里已有的住宿地点不会再进入日常地点池，也不会被夜间判定选中。

**Q：相册缩略图一直显示「加载中…」？**  
A：v1.5.4 已修复懒加载观察 hidden 图片导致永不触发的问题；重载插件并刷新页面即可。仍失败时会显示「缩略图失败，点击看大图」。

**Q：相册会一直变大吗？**  
A：默认最多保留 300 张，超出会自动删最旧的；原图和缩略图都在角色数据目录的 `album/`。相册每页显示 24 张，用「上一页 / 下一页」翻；看大图时双击可以放大那一处细节，放大后能拖动。

**Q：生图的时候切换标签页 / 关掉页面会失败吗？**  
A：不会。生图和 AI 生成都在服务端后台执行，切页、刷新、关掉页面都不会取消；回到工作台后会自动接管没跑完的任务，并在完成时提示（生图成功会直接把图打开）。只有重载插件或重启 AstrBot 才会丢失内存里的任务进度。

## 七、数据、备份与隐私

- 配置里的密钥只存在 AstrBot 配置中，别公开；
- 照片记忆、相册、日记、生活状态都在插件的数据目录；
- **素材库运行时也在数据目录**：`costumes.txt` / `closeup_prompts.txt` / `interaction.txt` / `meals.txt` 位于 `data/plugin_data/astrbot_plugin_selfie/`，插件包目录里的同名文件只是首次安装的默认值；升级或重装插件不会覆盖你改过的素材；
- **参考图页上传的图片也在数据目录**：`reference_images/library.json` 记槽位和条件，`<id>.png` 是原图（长边 ≤1536）、`<id>_thumb.jpg` 是页面缩略图；删掉整个 `reference_images/` 就等于把参考图页恢复成「没配置」状态，出图会回到原来的自动挑图；
- 想回退或搬家，先停 AstrBot，再备份**匹配的插件代码 + 配置 + 数据**；
- 新版本不再随包发布任何参考图，你上传的图只保存在自己的数据目录；不要把运行目录整体提交 Git；
- 参考图会发送给你配置的生图服务，请先确认该服务的隐私政策，并使用你有权使用的图片。
- v1.5.5 升级会做一次性事件素材库迁移（把旧事件正文抽成命名素材条目，必要时只补回缺失的大上海这一条事件）；重复升级不会重复迁移，迁移会提升 revision。
- v1.5.6 升级会为每个事件分配独立稳定 ID，并同步正在运行的事件状态引用；迁移记录持久后重复重载不会再次更换 ID。
- v1.5.15 升级会一次性清掉旧 `scenes.txt` 导入时拼进地点描述末尾的「|区|城市」后缀（只处理 `metadata.source = legacy_files` 的城市，地点条数和事件数据不变，重复加载不会重复清理）。清理后 `districts.txt` / `scenes.txt` 在本实例就彻底不参与运行了：只有 `workspace.json` **不存在**（全新安装或被你删掉）时才会再导入一次；想删可以先把这两个文件复制到备份目录，确认运行正常后再删，删之前请留一份，否则 `workspace.json` 丢失后无法再重建旧世界。
- 回退时请把**同版本的插件代码**、**升级前的工作台配置（workspace）**和**同一时点的运行状态**成对恢复：只恢复其中一个，会出现事件素材引用失效、事件 ID 对不上或城市/家配置不一致。对应的备份版本请向维护者确认，不要公开传播备份内容。

更细的迁移、模块说明和回退步骤见 [REFACTORING.md](<REFACTORING.md>)。

v1.5.15 是首个公开版本，把 v1.5.0 代码解耦重构以来的改进合并成一份说明（中间的小修复不再逐条列出），完整内容见 [CHANGELOG.md](<CHANGELOG.md>)：

- **架构**：main.py 精简为 AstrBot 适配层，业务逻辑拆进 `selfie_core/`，不依赖 AstrBot 即可离线测试（当前 377 项）；世界数据统一到 `workspace.json`，素材库支持网页增删改、稳定编号、引用保护与自动备份。

- **生图与工作台**：主站 / 副站生图、参考图编辑与失败降级；五页签工作台支持按地点（家 / 事件 / 过夜）测试、事件动作全量枚举并显示「名称：提示词」、素材试穿与 AI 辅助生成。
- **相册与日记**：相册翻页、缩略图按需加载、大图双击放大与拖动；生图与 AI 任务后台化（切页 / 关页继续）；日记由模型整理成五段式并同步到 LivingMemory。

仍需要注意：

- 聊天适配目前限定 aiocqhttp；
- 上传参考图仍需管理员填本地路径，没有网页上传向导；
- 新城市的地点与区域连接是模型生成的「生活模拟资料」，不是权威地图或真实交通时刻表；
- 城市名来自离线行政区资料快照，不保证最新行政调整；
- 出图效果最终取决于你的参考图和生图服务，离线测试通过不等于每张都满意；
- 离线检查通过不等于线上验收，实际效果以你的运行环境为准。
